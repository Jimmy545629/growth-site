## 一、动手之前是什么样

首页右下那张「今日自律行动」卡有三个勾选框，点一下会变绿、加删除线。
**但关掉网页再打开，全都没了。**

因为那时候完成情况只是存在内存里（`data.js` 里写死的 `done: true/false`），
页面上改的是内存里的一份副本，一刷新就回到初始值。

同一个问题还有另一处：顶栏写着「已连续自律 **12** 天」——
那个 12 是 `data.js` 里**写死的数字**，跟真实打卡毫无关系。

这两件事都属于同一类毛病：**页面上有个数字，但它是编的。**

Day 10 修的也正是这一类（统计卡的行动数字写死），
所以这次不是「顺手加个功能」，而是把同一条线继续做下去。

## 三、怎么做的

### 3.1 顺手把架构立起来（照老项目的规矩）

老项目 Day 6 定的技术规矩里有两条，正好是为今天准备的：

> 第 6 条：**数据读写只走 `assets/store.js`**，其他文件里禁止直接出现 `localStorage`
> 第 7 条：**常量只在 `assets/config.js`**

新项目原来只有 `data.js`、`app.js`、`style.css` 三个文件，
所以这次补上三个，形成一条清楚的流水线：

```
config.js  所有常量（存储键名、一天几项算打卡、显示最近几天）
   ↓
rules.js   所有「算」的逻辑 —— 全是纯函数，不碰存储、不碰页面
   ↓
store.js   所有数据读写 —— 全项目只有这一个文件碰 localStorage
   ↓
data.js    所有内容（语录、访谈、政策、有哪几件事）
   ↓
app.js     画到页面上 + 收用户的点击
```

**为什么值得这么拆**（这是本次最大的收获）：

`rules.js` 全是纯函数，意味着**不用开浏览器就能测**。
「连续天数数得对不对」是这次最容易出错的地方，
结果 58 条断言在命令行里 0.3 秒跑完，跨月、跨年、闰年、断档全都测了。
如果逻辑混在 `app.js` 里（要操作 DOM、要读存储），
就只能靠手动点页面去撞，撞不全。

### 3.2 记录长什么样

存在浏览器里的东西是这样一份数据：

```json
{
  "version": 1,
  "days": {
    "2026-09-26": ["read", "sport"],
    "2026-09-27": ["read", "sport", "review"]
  }
}
```

三个设计决定，每个都有原因：

**① 用日期当键**：一天一条，天然支持「往前翻记录」，
不用把「今天」单独存成特殊字段。

**② 存的是 id，不是「第几项」**：
每件事在 `data.js` 里有一个固定 id（`read` / `sport` / `review`）。
如果存的是「第 1 项、第 2 项」，那么以后改了文字、调了顺序、
甚至删掉一项，**以前的记录就会跟着错位**——昨天勾的「运动」明天可能变成「阅读」。

**③ 键名带版本号**（`growth-site.checkins.v1`）：
以后记录格式要改，换成 v2 就是新抽屉，
旧数据留在旧抽屉里不会被读错，也不会被误删。

### 3.3 连续天数怎么数（规则写在这里，免得以后忘了）

- 从今天往回一天天数，哪天没打卡就停在哪儿；
- **今天还没打卡时，从昨天开始数。**
  为什么：否则每天早上一打开就看到「连续 0 天」——
  昨天明明打了卡，感觉像被清零了；
- 「这天打过卡」= 当天至少完成 **1** 项（这个 1 在 `config.js` 里，想改改一行）。

## 四、路上踩到的三个坑（都记下来）

### 坑 1：日期不能用 `toISOString()`

第一版差点写成 `new Date().toISOString().slice(0, 10)`。
这是**最容易踩、又最不容易发现**的一个坑：

`toISOString()` 给的是 **UTC 时间**（世界统一时间），中国是 UTC+8。
也就是说**晚上 8 点以后**，它算出来的日期是「明天」——
你晚上 11 点打的卡会被记到第二天，第二天早上打开一看「今天已经打过了」。

改法：自己用 `getFullYear()` / `getMonth()` / `getDate()` 拼，
这三个拿的是**本地时间**。

验证脚本里专门留了一条断言守着这件事：
万一以后有人改回 `toISOString`，这条会当场变红。

### 坑 2：`add()` 只收一个子节点

顶栏那句「已连续自律 N 天」，第一版写成了：

```js
add(box, '已连续自律 ', h('b', { text: String(n) }), ' 天');
```

看着挺对，实际**只渲染出「已连续自律」**——
数字和「天」字全没了。

原因：`add(parent, child)` 这个函数只接收**一个**子节点，
多传的参数会被直接丢掉。
多层子节点要用 `h()` 来装（`h` 里面是循环处理每个子节点的）。

**这个 bug 是真机测试跑出来的**，不是读代码看出来的：
日志里「顶部写着『已连续自律 2 天』← 实际 "已连续自律"」那行，
就是它。如果没跑这一遍，打开页面第一眼看到的就是这个。

### 坑 3：关不掉浏览器（写了两次才关对）

要验证「关掉浏览器再打开，记录还在」，就得真的关掉再开。
结果第二个实例总是起不来，报「窗口没起来」。

查日志才明白：**当时只是给了命令，没说要看它的回显**——
把 `stdio` 从 `'ignore'` 改成接上 stdout / stderr 之后，
答案立刻出来了：`[exit] code=0`。

意思是：Edge 一看「这个档案已经有实例在跑」，
就把请求转发给那个实例，然后自己安静退出——新端口自然没人监听。

而第一个实例为什么没被关掉？
因为 `edge.pid`（用工具启动出来的那个进程号）**不是真正的浏览器进程**，
`taskkill /PID <它> /T /F` 杀了个空的。

改法：两道保险 —— 先按进程号杀进程树，
5 秒后如果调试端口还在响应，就改成**按「档案目录」匹配命令行**把整组进程杀掉。
（只杀命令行里带我们这个档案目录的，绝不碰用户自己开着的 Edge。）

## 五、验证结果

### 5.1 「算」的部分：58 / 58（`verify-checkin-rules.mjs`）

不开浏览器，直接在命令行里跑 `rules.js`。覆盖：

- 日期：晚上 11:30 仍算当天（不跳天）、零点刚过算新一天、月份补零
- 加减：跨月、跨年、闰年（2028-02-28 +1 = 02-29；2027 则是 03-01）、负数、加 0
- 脏数据：重复 id、空字符串、数字、对象、根本不是数组 —— 一律清洗成能用的
- 连续天数 12 种情况：空、只有今天、今昨前天、**今天没打卡从昨天数**、
  中间断档、跨月、跨年、混进未来日期、连续 40 天
- 最近 7 天：长度、正序、今天在最后、跨月边界、窗口外的记录不出现
- 汇总：完成项数 / 满打满算项数
