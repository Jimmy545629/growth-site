## Day 13｜2026-09-28　一个页面拆成三个视图 ＋ 列表补齐四种状态

**做了什么**

- 把原来「所有内容挤在一个页面」拆成三个能互相切换的视图：
  「今日」（`#/home`）、「内容库」（`#/library`）、「我的」（`#/me`）。
- 列表补齐**空 / 加载中 / 出错 / 正常**四种状态（以前只有「正常」一种），
  四种走同一个渲染器，出错留「重试」按钮。
- `PRD.md` 升到 **v1.1**。

**为什么这么做**

- **切换方式选「哈希地址」**（网址带 `#/home` 这类标记）。三条理由：
  ① 不引任何库，守住第 4 条零依赖的硬规矩，自己写不到一百行就够；
  ② 地址栏看得见 —— 你在哪一页，网址上就写着，**刷新还停在同一页**；
  ③ **浏览器返回键天然能用**，正好覆盖训练营清单里的「余力加练」。
- **切视图只改地址**（`location.hash`），其余交给 `hashchange` 事件统一处理。
  只有一个入口，就不存在「点导航一套逻辑、按返回键另一套」这种隐患。
- 内容库顶部加了一块「四种状态对照」演示区，**是为了让四种状态能一屏看到**
  （今天要交截图）。正式产品不会有这块，页面上也如实标注了。
- 先停下来问了一件事：`PRD.md` v1.0 写的是「**只有一个页面**，没有详情页、没有弹窗」、
  AC-14 写的是「页面上**没有**频道切换 Tab」——和今天的任务**方向相反**。
  按第 2 条规矩停下报告，Jimmy 点头后才改，并注明是 Day 13 的变更。
  **文档和代码不许打架。**

**怎么证明能用**

| 层级 | 怎么测的 | 结果 |
| --- | --- | --- |
| 命令行 | 不开浏览器，直接跑 `rules.js` 里的路由纯函数 | **78 / 78** |
| 真机 | CDP 驱动真 Edge，真点、真返回、真刷新 | **109 / 109** |

真机那 109 项覆盖：三视图互切 + 地址跟着变 + 导航高亮跟着变；
**浏览器返回键真的回到上一视图**；刷新后停在同一视图；
切数据源时先经过 0.42 秒「加载中」再变成目标状态；出错 → 点重试 → 重新读取 → 还是出错
（数据源就是「会失败」的那种，**不说假话**）；全程无 JS 报错。

截图四张（带地址栏）：`day13-view-home.png` / `day13-view-library.png` /
`day13-view-me.png` / `day13-four-states.png`，全部亲眼看过。

**顺手揪出的真 bug**：错误状态的重试按钮最早写死了 `id="btn-retry"`，
而它在页面上被画了两次（演示区 + 真列表）——**id 重复**，HTML 不允许。
真机测试点重试时，点到的是演示区那个没绑事件的按钮。

## Day 12｜2026-09-27　把「收藏」做实 ＋ 补上规矩文件

**做了什么**

- 收藏真的存进浏览器（`store.js` 里**单独一只抽屉**，不跟打卡混）。
- 语录卡底部加「我的收藏」列表，点一条能跳过去；没有收藏时整块不出现。
- 按钮状态改成**从存储里读**。
- 补上 `AGENTS.md`（9 条规矩）和 `PRD.md`（含第 9 节内容收录机制）。

**为什么这么做**

- 收藏原来有三个毛病叠在一起：① 状态存内存，刷新就没；② 用「第几条」当标识，
  改顺序就错位；③ **收藏完没有任何地方能看见**（等于扔黑洞）。
  第 ③ 条最值得说 —— 一个按钮按完看不到任何结果，它就不算一个功能。
- 语录加稳定 `id`，存的是 id 不是下标 —— 以后改文字、调顺序、删一项，旧记录都不会错位。
- `data.js` 底部把「当前引用来源」和「计划收录来源（尚未开始收录）」**分成两行**写，
  不许混在一起 —— 免得看的人以为页面上的内容已经出自那三个账号了。
  这是**内容诚实性底线**：不许凭印象写一句再挂上真人名字。

**怎么证明能用**

- 存储逻辑 **37 / 37**：Node 里造假窗口跑 `config → rules → store`，
  共用同一份假存储再跑一遍 = 模拟「刷新」和「关掉浏览器重开」。
- 真机 **58 / 58**：真开 Edge、真点按钮、真刷新、真关掉浏览器重开。
  最硬三条：刷新后仍在、关掉重开后仍在、取消收藏后刷新确认真的取消了。

详细记录见 [`docs/day12-favorites-persistence.md`](docs/day12-favorites-persistence.md)
和 [`docs/day12-content-collection.md`](docs/day12-content-collection.md)。

## Day 10｜2026-09-27　统计卡的行动数字不跟着勾选变

> 这一天的任务是「修一个真实的前端问题」，要求：截图 + 自然语言描述 + 验证。

**表现**：在下面把三项都勾上之后，上方「今日行动」统计卡还写着
`2 / 3 · 还差「睡前复盘 5 分钟」`，而下面那张卡已经是 `3 / 3` ——
**同一件事在同一屏里出现两个相反的说法**。

**原因**：这个数字在 `data.js` 里**另外写死了一份**；勾选改的是 `D.actions`，两处互不相干。

**改法**：把它标成 `from: 'actions'`，由 `app.js` 从 `D.actions` 现算，勾选时一并刷新 ——
让「今天完成几个行动」这件事**只有一个来源**。

详细记录见 [`docs/day10-action-stat-sync.md`](docs/day10-action-stat-sync.md)。
