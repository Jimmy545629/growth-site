## Day 20｜2026-10-06　跨域那一下：把浏览器摘掉，让服务器自己说话

> 今天的板块：① 确认云端数据面可用 ＋ 来源放行　② 本地接线　③ 重新发布　④ 逐项验证。
> 清单上「云函数」「检查台」「健康接口」三样本项目都没有，先报告、再按实际情况做。
> 完整记录见 [`docs/day20-cors-diagnosis.md`](day20-cors-diagnosis.md)。

**今天的一问：跨域那一下，你是怎么认出问题出在哪的？**

**做了什么**

**① 确认云端数据面可用 ＋ 来源放行**（只读探测，三种来源）：

| 请求带的来源 | 结果 |
| --- | --- |
| 网页自己的域名 | **200** |
| 故意换成别的域名 | **403** `access_denied — the request origin is not allowed for this client` |
| 完全不带来来源 | **200** |

中间那条 403 **就是 Day 17 踩过的那个坑的原话**，今天在命令行里**又复现了一遍**。

**② 本地接线**：把来源换成 `localhost` / `127.0.0.1` / `null`，**都是 200** ——
本地接线**本来就是通的**，今天**不需要改任何东西**。

**③ 重新发布**：本项目零构建，「重新构建上传」= 发布上线。发布前确认线上还是旧版，
发布后逐文件核对（`hot-updated` / `fetched_at` / `formatStamp` / `updatedLabel` 全部到位）。
线上地址没变。

**④ 逐项验证**：① 公网首页在真浏览器里从 DOM 实读到的是数据库真实数据
（榜单日期 2026-10-06、30 条中的 8 条）；② **控制台改一条标题 → 重开页面跟着变 → 再改回来**；
③ 页面真实发出的请求地址都在公网域名下。

**余力加练**：给首页「今日热点」加了「**最后更新**」那一格
（这份快照什么时候抓进云端的）。落点按老规矩分家：
`db.js` 多取一列 `fetched_at` / `cloud.js` 出参新增 `updatedAt` /
`rules.js` 新增纯函数 `formatStamp()` / `data.js` 放文案 / `app.js` 画 / `style.css` 上样式。

**为什么这么做**

- **「跨域怎么认出问题」的答案不是猜，是「只留一个变量」**：
  把同一个地址搬进命令行（不带来源）就是 200 → 排除「服务器挂 / 网络断 / 地址错」；
  再把「来源」这一个变量换成别的域名 → 服务器**自己开口**说 `access_denied`。
  结论是**服务器说出来的**，不是推理出来的。
- **为什么非得绕到浏览器外面问**：CORS 的报错对前端**故意不透明** ——
  浏览器不把服务器的真实原因交给页面脚本。所以那条含糊的 `TypeError: Failed to fetch`
  **不是故障信息，是设计如此**；答案在**服务器那边**。
- **「最后更新」为什么要跟「榜单日期」分开**：一个说「数据是哪一天的」，
  一个说「什么时候抓进来的」。哪天忘了跑同步任务，**两个一起停** —— 那正是要一眼看出来的东西。
- **为什么改数据要改回来**：往**真实数据**里动手，留一个「验证用的脏标题」就是给以后的自己挖坑。

**怎么证明能用**

- 规则层新建 `verify-day20-rules.mjs`，**27 / 27 通过**（垃圾值全部回落空串不抛错、
  补零与格式恒为 16 位、**按本地时间拼**、闰日 / 跨年零点边界、新旧时间函数并存没被合并）。
- 线上真机：DOM 实读三条完成标准逐项对上（见上）。
- **一个诚实的交代**：交付截图**第二次**才拍对 ——
  第一版「抓窗口没认到进程」（整条路径做 `-like` 匹配，反斜杠被当字面字符 → 查回 0 个进程 →
  退回「按面积最大」，**可能拍到 Jimmy 自己开着的同一个站点**），且**没滚到该拍的区块**（拍成了页面顶部）。
  两处都记在 `docs/day20-cors-diagnosis.md` 第七节。

**留下一条隐患（已发现，未改）**

`fetchHotTopics` 判「最新是哪一天」靠「按 `rank` 升序取回的第一行」，
而两份快照的 `rank` 都是 1…30，**并列时谁在前没有保证**。
今天连查 6 次都对（行物理顺序碰巧），但**不是规则保证的**。
按今天「不改后端 / 数据展示问题记录下来明天处理」的边界**没有动它**，
改法（一行）记在 [`docs/api-contract.md`](api-contract.md) 一·三。

## Day 19 收工后（补 2）｜2026-10-05 深夜　地址提醒 —— 让页面自己说清「你在哪儿」

> 这一条是**他点头才做的**（原话：「要给页面加一道「防呆提示」」）。
> 起因是同一晚他**第三次**报「我的收藏里看不到之前收藏的东西」。
> 详细过程见 [`docs/day19-favorites-visibility.md`](day19-favorites-visibility.md) 第八节。

**做了什么**

页面上多了一条**地址提醒**：只要当前地址**不是**正式网址，顶部就出现一条暖橙色提示，
说清三件事 ＋ 给一个出口：

| 它说什么 | 实际内容 |
| --- | --- |
| 你在哪儿 | 「你现在在这儿：本地文件（双击打开的那个 html）」／ `http://127.0.0.1:8078` |
| 你的记录在哪儿 | 「正式网址是：`https://source-board.app.workbuddy.host/`」 |
| 这个地址下有多少 | 「这个地址下：收藏 0 条 · 打卡 0 天」—— **当场从本地存储算的** |
| 出口 | 按钮「用浏览器打开正式网址」→ 跳到**正式网址上的同一页**（`#/me` 不丢） |

文案里有一句是这条提醒存在的**全部理由**：**「……不是丢了。」**

**为什么非要做**

同一晚他报了三次「收藏没了」，三次查下来都不是丢（见上一篇）。
前两次的应对都是**加解释**（先在空状态里补一句、再把收藏正文改成全文显示），
结果**他照样再问** —— 说明**藏在空状态里的解释不够**：
他看到的是「还没有收藏」这五个字，压根不会去读下面那行小字。

根子在于：浏览器的本地存储**按网址来源隔离**，而这个事实**在页面上完全没有体现** ——
页面永远是那副样子，看不出自己住在哪只抽屉里。
→ 所以这次不是**再解释一遍**，而是**让页面自己说**。

**怎么做的（守老规矩：常量 / 算 / 文案 / 画 / 样式 各归各位）**

| 放哪儿 | 放了什么 |
| --- | --- |
| `assets/config.js` | 常量 `officialOrigin`（⚠️ 注释写明它**必须等于** `cloud.endpoint`） |
| `assets/rules.js` | 纯函数 `isOfficialOrigin(origin, official)` —— 只比字符串，不碰浏览器 |
| `assets/data.js` | 文案段 `addrWarn`（⚠️ **故意不写地址**，两个地址都由 app.js 当场取） |
| `assets/app.js` | `renderAddrWarn()`：判断 ＋ 取数 ＋ 画（启动时一次，每次切视图再来一次） |
| `index.html` | 容器 `#addr-warn`，默认 `hidden` |
| `assets/style.css` | `.addr-warn` 一族 ＋ **`.addr-warn[hidden] { display: none; }`** |

⚠️ 三个**刻意**的选择，写下来免得以后被「优化」掉：

1. **连协议一起比**（`http` 和 `https` 在浏览器眼里是两个来源）。
   只比域名的话，用 http 打开会被误判成「就在正式地址上」——**该说的提醒反而不说了**，
   那比不写这个判断更糟。
2. **条数当场算，不缓存**。他刚在这个地址下收一条，数字就得跟着变；
   缓存的话这条提醒**自己就在说谎**（正是它要治的那个毛病）。
3. **地址不写死在文案里**，一律 `location.origin` / `config.officialOrigin` 现取 ——
   写死的地址迟早跟现实对不上（`PRD.md` C4 同一条道理）。

**怎么证明能用（三个模式各跑一遍，脚本 `verify-addr-warn.mjs`）**

| 模式 | 期望 | 结果 |
| --- | --- | --- |
| `local` 本地服务器（＝非正式地址） | 提醒**必须出现**，数字要跟着存储变 | **23 / 23** |
| `file` 双击本地文件 | 同上，且「你现在在这儿」要说人话（不能显示 `null`） | **15 / 15** |
| `live` 正式域名 | 提醒**必须完全不出现**，且版面没被动过 | **10 / 10** |

关键几条断言：正文里有「不是丢了」⭐ ／ 按钮指向 `正式网址 + #/me` ／
**不刷新页面、只切视图，数字当场从 1 条变回 0 条**（证明是算的不是缓存的）／
正式域名上容器里**一个字都没画**（不是画了再藏）／ 全程 JS 报错 **0 条**。

回归（我动了 `app.js` / `data.js`，必须重跑）：逻辑层 **73 / 73**、
线上全接口 **35 / 35**、收藏那条 **16 / 16**；
云端测试数据清干净（**21 行 / entry 13 条 / 残留 0**）。

⚠️ **两次「失败」都是我的测试写错，产品没问题**（又是上午那条坑的变体）：
① 用 `Page.navigate` 跳到**和当前完全一样**的地址，浏览器认为不必重新加载 → 改成 `Page.reload`；
② 断言「数字归零后正文变回『是空的』」，可我当时**把打卡那条留着了**（打卡 1 天），
   正文**正确地**仍是「也存了一份记录」—— 文案的判据是「两个数都为 0」，不是「收藏为 0」。

**没动的**：契约一个字没改；`store.js` 一行没改；
收藏 / 打卡**仍然不上云**（`PRD.md` 硬约束 C1 / C3 不变）。

**这一天学到的三件事**

## Day 18（续）｜2026-10-04　内容库能自己加一条了：第一个 POST 接口

> ⚠️ **编号说明**：昨天（10-03）那两条提交用的也是「Day 18」。
> 今天按 Jimmy 的清单继续用 Day 18，这里加「（续）」区分。

**今日学习点**：一个「提交」按钮，要防的是哪几种「不对劲的提交」？

**答案**：**两种 —— 一种防填错，一种防重复提交；而且两种都要防两层。**

| 防的东西 | 页面这层（为了快） | 数据库这层（为了真） |
| --- | --- | --- |
| 填错（缺必填 / 超长 / 形态不认识） | 当场回中文提示，**根本不发请求** | INSERT 策略的 `WITH CHECK` 再判一遍 |
| 重复提交（同一来源下标题已有） | 提交**前**先查一次 → `DUPLICATE` | `UNIQUE` 约束 → `23505` |

**「两层」是今天最值钱的一句**：页面那层是**体验**，数据库那层才是**安全**。
只有第一层的接口等于没防护 —— 页面代码能被绕过，表结构不会。

（完整答案、实测表、踩的坑 → `docs/day18-post-endpoint.md`）

---

**做了什么**

- **先定契约**：新建 `docs/api-contract.md`。把入参、出参、9 个错误码、每一句中文提示
  **先写死**，再照着它写代码。清单里「形状与 api-contract.md 一致」指的就是这个文件。
- **接口**：`assets/cloud.js` 加 `postEntry()`（校验 → 查重 → 写入 → 读回 → 统一形状）；
  另加 `validateEntry()`（纯函数）和 `fetchSources()`（表单下拉要用库里的真 id）。
- **表单**：「内容库」视图加了一块「新增一条」。`app.js` 画 + 收提交，
  `style.css` 给样式（**虚线边框**跟榜单区分开：上面是「看的」，这里是「动的」），
  `index.html` 加挂载点，文案进 `data.js`，数字进 `config.js`。
- **开权限**（`db/schema.sql` 的 Day 18 段，同步落到云端）：
  - `GRANT INSERT ON contents TO anon` —— **只给新增**，UPDATE / DELETE 一个字没给
  - `CREATE POLICY contents_insert_guard … WITH CHECK (…)` —— 字段校验 + 留痕字段不许伪造
  - `UNIQUE (source_id, title)` —— 防重复提交的最终防线
- **上线**：`https://source-board.app.workbuddy.host/`

**⚠️ 有一件事要单独说：这是全项目第一次「网页能写」。**

Day 16 / 17 定的边界是「网页只能读、不许写」。今天开了一个**只允许新增**的口子。
代价是**任何打开这个网页的人都能写一条**（这个项目不做登录，页面用的是匿名身份）。

**这不是漏想** —— 是摊开算过、然后选择接受的：

- **得到**：以后你自己在页面上就能加内容，不用再走「改 data.js → 找 AI → 提交 → 推送 → 发布」那一圈；
- **换来**：管不住「谁来写」，就**把门开小** —— 只给 INSERT（不能改不能删）、
  字段长度卡死、`kind` 和 `media` 限定取值。

**余力加练：加一条服务端日志**

这个项目**没有服务器**（纯静态页面 + 托管数据库），所以能「在服务端记一笔」的地方
只有**数据库自己**。做法：给 `contents` 加一列 `created_via`，
默认值填 `current_user` —— 网页写的记成 `anon`，维护者通道写的记成管理员角色名。

⭐ **重点不是「加了这一列」，而是它改不了**：前端要是自己塞一个 `created_via:"admin"`，
INSERT 策略里那条 `created_via = current_user` 会当场把它顶回去（`42501`）。
**一份能被写的人自己改的记录，等于没有记录。**

**验证怎么做的**（都真跑过，不是「应该没问题」）

| 试的事 | 结果 |
| --- | --- |
| 空标题点提交 | 「标题不能为空」+ `MISSING_TITLE`（**这一步没发网络请求**） |
| 不选来源点提交 | 「请选择一个来源」+ `MISSING_SOURCE` |
| 正常提交（线上真地址） | `{ok:true, id:"u-2026-10-04-2kw", …}`，形状与契约完全一致 |
| **同一条再交一次** | `{ok:false, code:"DUPLICATE", message:"这条内容已经在库里了…"}` |
| 回查数据库 | **真的多了一行** · 总行数 20 → 21 |
| 伪造 `created_via:"admin"` | 被数据库拒：`42501 new row violates row-level security policy` |
| 页面 JS 报错 | **0 条** |

**踩的两个点**

1. **空数组 ≠ 成功。** RLS 把写入挡住时，PostgREST **不给 error**，只给一个 `data: []`。
   当成成功处理，就会出现「页面说存好了、库里什么都没有」——**比报一串错还糟**，
   因为没人会去查它。所以 `insertEntry()` 里专门判了这一条，宁可报 `WRITE_FAILED`。
2. **「先查后写」拦不住并发。** 提交前那次查询只是为了让**提示准**
   （一句中文，而不是一串英文错误码）。两个人同时提交时它拦不住 ——
   真正的防线是唯一约束。**任何「先查再写」的逻辑都要问一句「两个人同时做会怎样」。**

## Day 18｜2026-10-03　整页铺上了 Jimmy 自己拍的视频

> ⚠️ **这条是「先做完、等他看了才提交」的**。Jimmy 原话：
> 「该给我看看吧，如果更改完善后，某些地方冲突太大，我再复原」。
> 所以顺序是：做出来 → 截图给他看 → 他说「行」→ 才写这条日志、才提交。

**今日学习点**：一段看着没问题的视频，为什么浏览器根本不播？

**答案**：**编码格式不对，而且是从源头就不对。**

Jimmy 给的是手机拍的 `.mp4`。肉眼看着是个正常视频文件，
但浏览器里**完全不播**。查法是三行 JS：

- `canPlayType('video/mp4; codecs="hvc1"')` → 返回**空字符串**（不是 "maybe"，是空）
- 真去加载 → 报 `MEDIA_ELEMENT_ERROR: Format error`（错误码 4）

**根因**：原始文件是 **HEVC / H.265** 编码。
Chromium 系浏览器（Edge / Chrome）**出厂不带 H.265 解码器** ——
H.265 有专利授权费，浏览器厂商默认不装。
**「文件能打开」和「浏览器能播」是两件事**，这是今天最值钱的一句。

---

**做了什么**

- **转码**：用 `imageio-ffmpeg` 自带的 ffmpeg，把 H.265 转成 **H.264**：

  ```
  ffmpeg -y -i "原视频.mp4" -c:v libx264 -preset slower -crf 30 -pix_fmt yuv420p \
         -an -vf "setpts=1.5*PTS,scale=1104:-2" -r 24 -movflags +faststart \
         "assets/hero-sea.mp4"
  ```

  - `-an` 去音轨（背景视频不需要，还能瘦身）
  - `setpts=1.5*PTS` **慢放 1.5 倍** —— 原片动得偏急，慢下来才像「氛围」不像「GIF」
  - `+faststart` 索引挪到文件头，边下边播
  - CRF 试了三轮：23 → 1.76MB 偏大；26 + 放大到 1280 → 1.81MB（**放大反而更大**）；
    **30 保持原尺寸 → 1.01MB**，画质够用

- **新增 `assets/hero-video.css`** —— 视频背景的**全部**样式，单独一个文件。
  想关掉只要删 `index.html` 里一行 `<link>`，不用在 `style.css` 里到处摘代码。

- **`index.html` +28 行** —— 一个 `<link>` + 一个 `.bg-video` 块（`<video>` + 压暗层）。

- **新增 `assets/hero-sea.mp4`**（转码后，1.01MB）、**`assets/hero-sea-poster.jpg`**（89KB，网慢时先显示）。

**没动的**：`style.css` / `app.js` / `config.js` / `data.js` / `rules.js` / `store.js`
**一行都没改**。视频层是纯装饰、不在 JS 必经路径上，不挂 `onerror`。

**为什么这么做**

- **三层结构**：`.bg-video`（`position: fixed`，铺满）→ `.veil`（压暗层）→ `.wrap`（原内容）。
- **卡片换成「半透明 + 磨砂」**：原来是不透明深蓝卡片，压到视频上就是一坨死黑板，视频白铺了。
- **视频「上下两头淡出去」**：用 `mask-image` 让视频顶边和底边渐变到页面底色，
  这样顶栏 / 大标题压在上面也不会跟画面打架。**这一步是踩了两个坑之后才找到的**（见下）。

**怎么证明能用**

| 检查项 | 结果 |
| --- | --- |
| 视频能否播放 | 能播 · 1104×720 · 8.5 秒 · 循环 · 无声 |
| 转码后体积 | 1.01MB（转码前那个根本播不了） |
| 文字最低对比度 | **5.08 : 1**（WCAG AA 要求 ≥ 4.5 : 1） |
| 视频读不到时页面是否可用 | **可用** · 打卡能存进 localStorage · **JS 报错 0 条** |
| 三个视图 | 首页 / 内容库 / 我的，逐个点导航标签截图确认 |
| 页面是否还能滚动 | 是（页面总高 2684px） |

**对比度怎么量的（不是靠眼睛看）**：写了脚本，先用 canvas 抽帧找出视频
**最亮的那一秒**并钉住，再逐个元素算「文字色 vs 层叠出来的底色」的 WCAG 对比度。
最低 5.08。**判断标准不是「好不好看」，是全片每一帧都读得顺。**

**「视频读不到」怎么模拟的**：
`Network.setBlockedURLs(['*hero-sea.mp4*','*hero-sea-poster.jpg*'])`。
结果：视频 `readyState 0`，但统计卡 3 张、导航 3 个、大标题、语录卡、底栏**全在**，
点「读完了」成功写进 `growth-site.daily-reads.v1`，**JS 报错 0 条**。
→ 这条直接印证了 PRD 硬约束 **C1**（核心功能不依赖服务器）。

**⚠️ 今天踩的四个坑（都只有真跑起来才看得见）**

1. **`backdrop-filter` 做的「磨砂托底」，边界藏不住。**
   想给顶栏 / 导航加托底，做成「圆角矩形 + `blur(10px)`」——
   结果边界清清楚楚，顶上像贴了张**浅蓝膏药**。
   根因：`backdrop-filter` 只模糊元素矩形**范围内**的背景，矩形外不模糊 → 直边必然可见。
2. **改用纯渐变后，半径写太小又出硬边。**
   `radial-gradient(130% 150% ...)` —— 元素只有几十像素高，
   渐变**还没走完就被元素边界裁掉**，出现一块带硬边的暗色矩形，比坑 1 还明显。
   **✅ 最终解法：把视频自己上下淡出（`mask-image`）。**
   `mask` 本来就是「渐隐」，压根不存在边界这回事。
   > 教训：想让某块「边缘淡出」，用 `mask`，不要「给它垫一个带渐变的兄弟元素」。
3. **类名凭印象瞎写，写错的完全没生效。**
   我写了 `.demo-cell` 和 `.entry-item` —— **两个都不存在**（真实是 `.demo-card` / `.entry`）。
   现象是「内容库那四格压在视频上像四块黑板」。顺带发现 `.entry` 是**带下划线的列表行**，
   不是色块，**不能**给它加背景。
4. **bash heredoc 写出来的脚本，反斜杠被吃掉（最阴的一个）。**
   在 `cat > x.mjs <<'SCRIPT'` 里写 `'C:\\Users\\...'`，JS 解析时 `\U` 不是合法转义被丢弃
   → 路径变成正斜杠 → 跟 `path.join` 拼出的反斜杠比 `startsWith` 得 false
   → **静态服务每个请求都 404** → 浏览器打开的是 **Edge 错误页**。
   **症状极阴**：脚本不报错、服务照常起、浏览器照常开，只有「页面内容不对」一个线索。
   我因此**截了一堆「看着像页面、其实是错误页」的图**，还对着它们分析「为什么滚不动」
   （错误页只有 360px 高，当然滚不动）。
   > 教训：**脚本一律用编辑器「写文件」写，不要用 bash heredoc。**
   > 另外静态服务要自测：先 `fetch` 一下 `index.html` 看是不是 200，再开浏览器。

**顺带修的一个小坑**：本地小服务必须支持 **Range（206）**。
`<video>` 一定会发 Range 请求（边下边播、能拖进度条），
只回 200 的话 Chromium 会停在 `readyState 0` 不动 ——
现象是「页面看着正常、视频完全没加载」。

> ⚠️ **但这条只对本地那个手写小服务成立。** Day 18 发布后我又对着线上真地址验了一遍：
> 线上对 `Range` 请求回的也是 **200 而不是 206**，可视频照样播得好好的
> （`readyState 4`、进度在走）。说明线上那台服务器/反代自己处理得过来，
> **不要照着这条去线上重复折腾 Range**。

**发现方式**：在 B 上跑 `list_tables`，返回的只有 auth / storage / internal 几个系统
schema —— 我自己建的表**一张都不在**；再查 `sources` 直接报
`42P01 relation "sources" does not exist`，
而 `sources` 明明在 A 里躺得好好的。**「同一个名字，两个库里各有一半」，就是这么发现的。**

**做了什么**

- **新增 `assets/cloud.js`** —— **全项目唯一允许碰云端的文件**。
  - `waitForSdk(timeoutMs)`：**轮询等 SDK 到位**（最多 6 秒），等到才认「真的没有」。
  - `buildClient()`：只建一次客户端（建两次会多一倍请求）。
  - `fetchHotTopics(limit)`：读 `hot_topics`，取**库里最新那一天**的整份榜单，
    返回 `{ ok, rows, date, total }`；读不到就返回 `{ ok:false, reason }`。
  - `localDate()`：用**本地时间**拼日期（`toISOString()` 给 UTC，晚上 8 点后会算成第二天）。
- **`index.html`**：加云端 SDK（CDN）+ `cloud.js`，加「今日热点」容器；
  **修掉一个线上才看得见的坑**（见下）。
- **`assets/app.js`**：新增 `renderHot()`（先画骨架再去读）、`paintHot()`（三种结局分头画）。
- **`assets/data.js`**：加 `hot` 文案块（标题 / 日期 / 来源 / 三种失败说法 / 重试）。
- **`assets/style.css`**：加「今日热点」区块样式（F15）。
- **新增 `db/sync-hot.mjs`** —— 热搜同步任务：从 **60s.viki.moe** 拉百度实时热搜，
  生成 SQL 写进 `hot_topics`。**它是「造 SQL」，不是「直接写库」**（原因见下）。
- **云数据库**：在**正确的那个应用**里建 `hot_topics` 表（11 列）+ 索引 + RLS 两道门 +
  表注释；灌入 **30 条**当日真实热搜。
- **余力加练**：地址支持 `?hot=N` 控制显示条数（`1 ~ 30`）——
  `rules.js` 新增 `hotLimitFromHash()` 纯函数专管校验；`config.js` 加 `hot.limitMax`。

**为什么这么做**

- **为什么 `cloud.js` 要单独一个文件**：跟 `store.js` 同一条规矩（老项目 Day 6 第 6 条）——
  **把「数据从哪来」关在一个文件里**，页面代码一个字都不用知道数据是来自本地抽屉还是云端。
  以后要换数据源，只改这一个文件。
- **为什么必须有 `waitForSdk` 轮询**：第一版写的是「跑的时候看一眼，没有就返回 `no-sdk`」。
  结果首屏**经常**误报「云端组件没加载成功」，而 SDK 其实好好的 ——
  外部脚本是异步下载的，**我的代码可能比它先跑到**。
  → 记牢：**「现在还没有」和「根本没有」是两件事**。
- **为什么同步脚本只造 SQL、不直接写库**：Day 16 定的边界 —— 网页只能读、不许写。
  实测用网页那把钥匙去 POST 写入，服务端返回
  `HTTP 401 {"code":"DATABASE_42501"}`。**这不是坏了，是边界在生效。**
  所以入库走**维护者通道**（本机跑脚本 + 提权写入），跟线上网页那条通道分开。
- **为什么取「库里最新那一天」而不是死认「今天」**：首页不该在零点过后就空掉；
  万一某天忘了跑同步，显示最近一份当日榜单比显示空白有用得多。
  **同时把日期一起显示出来**，让人能分清这是哪天的。
- **为什么 `endpoint` 必须和网页自己的域名完全一致**：
  服务端按**来源（Origin）精确匹配**。用错了会被一口回绝
  `HTTP 403 {"error":"access_denied","error_description":"the request origin is not allowed for this client"}`。
  **最坑的是浏览器不告诉你这个 403** —— 它统一报 `TypeError: Failed to fetch`，
  看起来像断网；而**不带 Origin 的 curl 却是 200**，于是极容易查错方向。
- **为什么 `?hot=N` 要封顶 30**：库里一天就 30 条；写 99999 只会让页面白等、白画一堆骨架，
  一个手抖就能把首屏撑爆。认不出来（`hot=abc`、`hot=2.5`、`hot=0`）**一律静默回默认** ——
  跟其它「外面来的数据」一样，**不许因为一个手抖就白屏**。

**怎么证明能用**

1. **HTML 行尾注释陷阱**：原来写成

## Day 10｜2026-09-27　统计卡的行动数字不跟着勾选变
