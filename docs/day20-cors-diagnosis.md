## 〇、先回答今天的一问

> **「跨域那一下，你是怎么认出问题出在哪的？」**

### 当时的表面现象

浏览器控制台只给了一句话，看着像断网：

```
TypeError: Failed to fetch
```

⚠️ **这句话本身几乎不含信息**：它不说是域名不对、权限不对、还是网络断了。
Day 17 那次就是卡在这里 —— 看起来像「网不通」，于是往网络方向找，白找。

### 认出问题的办法：**只留一个变量**

真正管用的不是「猜」，是**把变量一个一个摘掉**，直到剩下一个还在动的。
四步，每步只改**一件事**：

| 步骤 | 我做了什么 | 结果 | 排除了什么 |
| --- | --- | --- | --- |
| 1 | 把**同一个地址**搬进命令行（**不带来源**） | HTTP **200**，返回真实数据 | **服务器没挂、网络没断、地址没写错** |
| 2 | 手动带上**正确的来源**（网页自己挂的那个域名） | HTTP **200** | **权限本身是通的** |
| 3 | 只把「来源」换成**别的域名** | HTTP **403** | ← **问题就在这里** |
| 4 | 看**服务器自己说的话** | `access_denied — the request origin is not allowed for this client` | 原因被**服务器亲口讲出来**了 |

> **第 3 步那一下就是关键**：换掉的只有「来源」这一个变量，
> 其余（地址、鉴权头、方法）一个字没动 ——
> 结果**只有它变了**，那它就是那个变量。

### 为什么结论是「服务器说的」，不是「我推出来的」

第 4 步那句 `access_denied … origin is not allowed` 是**服务器返回的正文**，
不是我们的判断。这就是「只留一个变量」的目的：

> **把浏览器摘掉，好让服务器直接开口。**

### 顺带把一个疑问解掉：为什么浏览器只说「Failed to fetch」

因为 **CORS 的报错对前端是故意不透明的** —— 浏览器出于安全，
**不把服务器的真实原因交给页面脚本**（否则页面就能拿它探测内网）。
所以那条含糊的 `TypeError` **不是故障信息，是设计如此**。

→ 于是「怎么认出问题」这件事，**在浏览器里问不出答案**，
必须**绕到浏览器外面**（命令行 / 后端日志）去问**服务器本人**。

### 一句话总结今天的这一问

> 认出问题不靠猜，靠**只留一个变量**；
> 而跨域这一类问题，**答案在服务器那边**，不在浏览器这边 ——
> 所以第一步永远是：**把同一个请求搬到命令行，重放一遍。**

## 二、板块①：确认云端数据面可用 ＋ 来源放行

对 `/.cloud/database/rest/hot_topics` 做**三种来源**探测（只读，一个字没改）：

| 我发的请求带什么来源 | 结果 | 服务器原话 |
| --- | --- | --- |
| 网页自己的域名 `https://source-board.app.workbuddy.host` | **200** | 返回真实热搜 |
| 故意换成 `https://example.com` | **403** | `access_denied — the request origin is not allowed for this client` |
| **完全不带来来源** | **200** | 返回真实热搜 |

> 中间那条 403 **就是 Day 17 踩过的那个坑的原话** —— 今天在命令行里**又复现了一遍**。
> 复现出来，才说明「我当时没有猜」。

**结论**：云端数据面**可用**；来源白名单**已配置**（只放行网页自己的域名）。

## 三、板块②：本地接线

同样的探测，只把「来源」换成**本地地址**：

| 请求带的来源 | 结果 | 说明 |
| --- | --- | --- |
| `http://localhost:8063` | **200** | ✅ 本地服务器打开时，云端放行 |
| `http://127.0.0.1:8063` | **200** | ✅ 同上（两个写法都放行） |
| `null` | **200** | ✅ 浏览器双击本地文件打开时发的就是 `Origin: null`，所以**双击也放行** |
| `file://`（直头写这个） | **403** | ⚠️ 这是**我手写的假头**；真实浏览器**不会**发 `file://`，它发的是 `null`（见上一行） |

**结论**：本地接线**本来就是通的**，今天**不需要改任何东西** ——
白名单里早就含了 `localhost` / `127.0.0.1` / `null`。
（这一点值得记：**跨域不是「每次都坏」，配好一次就一直好**。）

## 五、余力加练：给首页「今日热点」加「最后更新时间」

清单要的是给「检查台」加「最后更新时间」；检查台不存在，
于是把它加在**首页「今日热点」区块**上 —— 那里本来就是「一份快照」，
加一行「这份快照什么时候抓进来的」最自然。

### 5.1 它跟「榜单日期」不是一回事（这是这块设计的要点）

| 显示 | 回答 | 例 |
| --- | --- | --- |
| 榜单日期 | 这份数据是**哪一天**的 | 榜单日期：2026-10-06 |
| **最后更新** | 我们**什么时候**把它抓进来的 | **最后更新：2026-10-06 22:57** |

> 某天**忘了跑同步任务**时，这两个数会**一起往后停** ——
> 那正是这一格存在的理由：**让「数据几天没更新」一眼可见**。

### 5.2 改了哪些文件（守项目的老规矩：常量 / 算 / 文案 / 画 / 样式 各归各位）

| 放哪儿 | 放了什么 | 为什么放这儿 |
| --- | --- | --- |
| `assets/db.js` | `.select(…)` 里**多取一列** `fetched_at` | 取数据是这一层的事 |
| `assets/cloud.js` | `fetchHotTopics` 出参**新增** `updatedAt` | 编排 / 保证形状属于接口层 |
| `assets/rules.js` | **新增纯函数** `formatStamp(iso)` → `YYYY-MM-DD HH:mm` | 「算」必须放纯函数层，能命令行单测 |
| `assets/data.js` | 文案 `updatedLabel: '最后更新：'` | 文案只放文案 |
| `assets/app.js` | `renderHot` 里多画一格 `.hot-updated` | 这一层只负责「把字摆上去」 |
| `assets/style.css` | `.hot-updated`（比「榜单日期」**淡一档**，主次分开） | 样式只放样式 |

⚠️ 三个**刻意**的选择：

1. **换算只在 `rules.js`（纯函数）**，`app.js` 只摆字符串 —— 因为纯函数能命令行测。
2. **一律按本地时间拼**，**禁用 `toISOString()`** —— 中国是 UTC+8，用 UTC 拼会整整差 8 小时。
   （项目里「日期一律用本地时间拼」这条老规矩，这次同样适用。）
3. **认不出来（空 / 乱码）就返回空串，那一格就不画** ——
   既不印 `undefined`，也不编一个时间出来。

### 5.3 怎么证明（规则层，命令行直接跑）

新建 `verify-day20-rules.mjs`，**27 项全过**：

```
node .workbuddy/tools/verify-kit/verify-day20-rules.mjs
→ 通过 27 项，失败 0 项
```

覆盖：垃圾值**全部回落空串且不抛错**、补零与格式（`YYYY-MM-DD HH:mm` 长度恒为 16）、
**本地时间**（拿「本地时刻」转成 UTC 串喂进去，要求原样还原 —— 在任何时区都测得出有没有偷偷按 UTC 拼）、
闰日 / 跨年零点边界、新旧两个时间函数**并存没被合并**。

## 八、今天记录的一条隐患（**已发现，未改**）

`fetchHotTopics` 判「库里最新是哪一天」靠的是「按 `rank` 升序取回的第一行」。
⚠️ 两份快照的 `rank` **都是 1…30**，并列时谁在前**没有保证**。

- Day 20 实测**连查 6 次，都返回 `2026-10-06`**（今天）—— **这次是对的**，
  但那是**行的物理顺序**碰巧给的，**不是规则保证的**。
- **今天为什么不改**：任务边界写明「不改后端 / 数据展示问题记录下来明天处理」，
  而它**当下不表现为故障**（页面显示的确实是今天的数据）。
- **建议怎么改（见 `docs/api-contract.md` 一·三，未实施）**：
  `assets/db.js` 里那句 `.order('rank', { ascending: true })` 改成
  `.order('topic_date', { ascending: false }).order('rank', { ascending: true })` ——
  一行改动，`all[0]` 从「碰巧」变成「**保证**」。
