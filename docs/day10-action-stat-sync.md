# Day 10｜统计卡的行动数字不跟着勾选变

> 今天是「第 2 周」的第一天，练的是同一件事：**你怎么描述那个问题，让 AI 一次就改对了。**
> 所以这份记录的重点不是「改了什么代码」，而是**那段描述里到底写清了什么**。

---

## 一、先说结论

| | |
| --- | --- |
| 问题 | 首页上方「今日行动」统计卡的数字**不会跟着下面勾选变** |
| 影响 | 同一件事在同一屏里出现两个相反的说法，用户不知道该信哪个 |

## 二、问题长什么样（这就是「截图定位」那一步）

在页面上把「今日自律行动」的三项**全部勾上**，然后往上瞟一眼：

```
┌──────────────────────┐
│  今日行动             │   ← 上方统计卡
│  2 / 3               │
│  还差「睡前复盘 5 分钟」│
└──────────────────────┘

┌──────────────────────┐
│  今日自律行动          │   ← 下方行动卡
│  ☑ 阅读 20 页         │
│  ☑ 运动 30 分钟       │
│  ☑ 睡前复盘 5 分钟     │   ← 明明打上勾了
│  今天已完成 3 / 3      │
└──────────────────────┘
```

**上面说「还差睡前复盘 5 分钟」，下面那个「睡前复盘 5 分钟」正打着绿勾。**

它俩说的是同一件事：今天做完了几个行动。
一个说 2 个，一个说 3 个。**这就是问题。**

### 为什么一定要先截图

因为「点了不反应」这类问题，**光读代码很容易看漏**——
`data.js` 里写着 `value: '2'`，`app.js` 里写着读 `D.actions`，两个文件各自看都没毛病。
只有把页面点一遍、把两个数字摆在一起看，矛盾才暴露出来。

## 三、那段让 AI 一次就改对的描述

原话大概是这样的（四句话）：

> **1. 在哪儿：** 首页最上面那三张统计卡，**中间那张「今日行动」**。
> **2. 我做了什么：** 我在下面「今日自律行动」里把三项**全部勾上**。
> **3. 我看到了什么：** 上面那张卡还是 `2 / 3`、还写着「还差『睡前复盘 5 分钟』」；
>    可下面那张卡已经变成 `3 / 3` 了。
> **4. 我希望它怎样：** 这两处应该**永远是同一个数**，勾了哪个就跟着变。

**为什么这样描述就够了**——它把四件事都钉死了：

| 描述里的要素 | 作用 |
| --- | --- |
| 在哪儿（统计卡中间那张） | 全页有三张统计卡，不说清就得靠猜 |
| 我做了什么（勾满三项） | 给出**可复现的步骤**，AI 能照做一遍 |
| 我看到了什么（2/3 vs 3/3） | 给出**事实**，不是「感觉不对」 |
| 我希望它怎样（两处同一个数） | 给出**判断标准**，改完能验收 |

反过来说，下面这些说法就没用，AI 只能反问或乱猜：

- ❌「首页的数字好像不太对」—— 哪个数字？哪张卡？
- ❌「统计卡有问题」—— 什么情况下有问题？现在看着挺正常
- ❌「帮我优化一下首页」—— 优化什么？没有标准，AI 只能自己发挥（多半改错地方）

**一句话：把「在哪儿 + 怎么复现 + 事实是什么 + 期望是什么」说全，AI 一次就能改对。**

## 四、原因

「今天完成了几个行动」这件事，在代码里有**两个来源**：

```
data.js   stats[1] = { value: '2', unit: '/ 3', note: '还差「睡前复盘 5 分钟」' }   ← 写死的
   ↑ 页面第一次渲染时读它

data.js   actions[] = [{ done: true }, { done: true }, { done: false }]            ← 会变的
   ↑ 你每点一下勾选，改的是这里

app.js    renderActions() 读 actions 算出 3 / 3
          ↳ 但它**不会**去更新上面那张统计卡
```

`renderStats()` 只在页面刚打开时跑那一次，之后**再也没人叫它**。
所以勾选只会刷新下面那张卡，上面那张从头到尾没动过——它显示的永远是打开页面那一瞬间的数。

> 这类问题有个通用名字：**同一份数据被复制成了两份**。
> 只要有两份，早晚会对不上。修法不是「让它俩一起改」，而是**让它只剩一份**。

---

## 五、改法（只改这一处）

### 1. `data.js`：那一张不再写死数值

```js
{ label: '今日行动', from: 'actions' },     // 数值和说明都从 D.actions 现算
```

### 2. `app.js`：新增一个「现算」的函数，两处共用同一套算法

```js
function countDone() {
  return D.actions.filter(function (a) { return a.done; }).length;
}

function actionStat() {
  var total = D.actions.length;
  var left = D.actions.filter(function (a) { return !a.done; });
  return {
    value: String(total - left.length),
    unit: '/ ' + total,
    note: left.length === 0
      ? '三项都做完了，保持住'
      : '还差「' + left.map(function (a) { return a.text; }).join('、') + '」'
  };
}
```

### 3. `app.js`：勾选之后，上面那张卡一起刷新

```js
function toggle() {
  D.actions[i].done = !D.actions[i].done;
  renderActions();
  renderStats();     // ← 新增这一行
}
```

**关键不是多写一行刷新，而是让这个数字只剩一处来源。**
上面那张卡的 `2 / 3`、下面那张卡的 `3 / 3`，现在都是同一个函数算出来的，
**结构上就不可能再对不上**。

## 六、验证

用的是真机点击（不是读代码猜）——起本地服务、开一个真浏览器窗口、
用调试接口**真的点三下**，然后把两处数字读出来比对。

### 修复前

```
点之前    →  统计卡 2 / 3  |  行动卡 2 / 3   →  对得上
点满三项  →  统计卡 2 / 3  |  行动卡 3 / 3   →  ⚠️ 对不上
```

### 修复后

```
点之前    →  统计卡 2 / 3  |  行动卡 2 / 3   →  对得上
点满三项  →  统计卡 3 / 3  |  行动卡 3 / 3   →  ✅ 对得上
```

## 七、下次怎么避免

**同一个事实，只允许在代码里存在一处。**

如果某个数字页面上要显示在两个地方，那就：
1. 只存一份（存在会变的那个数据里）；
2. 写一个函数把这份数据翻译成要显示的文字；
3. **两个地方都调这个函数**，而且一处数据变时，两个地方一起重画。

——凡是「页面上两处显示同一个东西」，都值得顺手核对一遍它们是不是同一个来源。
