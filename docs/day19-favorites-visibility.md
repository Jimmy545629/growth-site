## 一、他原话

> 「还有我今天发现我的收藏里面，我之前收藏的东西没有了，帮我把收藏的记忆功能给我好好优化一下」

## 二、第一件：东西根本没丢（附可复用的排查手法）

他说「没有了」，但我不能凭猜。做法是**直接去浏览器里把那份记录读出来**。

### 先说一个反直觉的点

⚠️ **不能只看磁盘上的数据库文件。**
浏览器的本地存储用的是 leveldb，它**删东西只写一个「删除标记」，旧字节仍然留在文件里**。
所以在文件里 `grep` 到某个值，**不等于**它现在还生效。
**唯一说了算的是浏览器自己。**

### 这次的步骤

| 步骤 | 做什么 | 脚本 |
| --- | --- | --- |
| 1 | 找到浏览器档案下的 `Local Storage/leveldb/` 目录，**复制**一份出来（原文件被浏览器锁着，只读复制，不碰原件） | `scan-v2.py` |
| 2 | 在这一份里搜键名，先看出「数据在不在、属于哪个网址来源」 | `scan-v2.py` |
| 3 | 把这份副本**摆进一个隔离档案**（新建的 `--user-data-dir`），用它打开**同一个域名**，问浏览器 `localStorage.getItem()` | `read-fav.mjs` |
| 4 | 顺手把副本**备份**到别处 —— 排查途中弄丢唯一一份数据是最糟的结局 | — |

### 读到的结果

```
网址来源：https://source-board.app.workbuddy.host
里面存着：growth-site.favorites.v1 = {"version":1,"ids":["inamori-effort"]}
         growth-site.checkins.v1  = {"version":1,"days":{"2026-09-30":["sport"]}}
```

而且同一份数据下，「我的」页画得**完完整整**：
「我的收藏 1 条 —— 付出不亚于任何人的努力，是自然界存在的规律。（稻盛和夫）」。

**结论：没有 id 对不上、没有版本不符、没有被清空 —— 一条都没丢。**

### 那为什么他会觉得「没了」

**浏览器的本地存储是按「网址来源」完全隔离的。** 同一个网页，用不同方式打开，
浏览器认为它们是**三个不同的地方**，各存各的：

```
双击本地文件  file://                                  ← 空的
早期测试用的  http://localhost:8063                     ← 空的
线上网址      https://source-board.app.workbuddy.host   ← 收藏在这一只里
```

我把他的存储整个翻了一遍：**只有线上那个网址底下有数据，`file://` 和 `localhost` 一处都没有。**
只要他不是用线上网址打开的，「我的」页就必然是空的 —— **那不是丢，是打开方式不同。**

## 三、第二件：他说的「不方便看」才是真问题

他后来补的那句话才是重点：

> 「只要我点到我的收藏就可以看到历史收藏，而（不是）之前收藏的东西无法直接看到，
> 还需要点某个链接才能查到，太不方便看了」

对照代码，**两处病根**：

### 病根 1　正文只露半句

```css
/* 改之前 */
.fav-text {
  flex: 1; min-width: 0;
  font-size: var(--fs-4);        /* 13px，而且是「辅助」档 —— 列表正文比正文还小 */
  overflow: hidden;
  text-overflow: ellipsis;       /* 超出打省略号 */
  white-space: nowrap;           /* 强制一行 */
}
```

每条只显示一行，超出直接变成「…」。**想看全文必须点走** —— 这就是他说的
「无法直接看到，还要点某个链接才能查到」。

**收藏夹的意义就是「回头还能读到」，只看得见半句等于白收。**

### 病根 2　对不上的 id 被静默跳过

```js
ids.forEach(function (id) {
  var q = quoteById(id);
  if (q) items.push(q);   // ← 找不到就悄悄丢掉
});
```

数据明明还在浏览器里，页面却显示「一条都没有」。
**这等于界面在说谎** —— 而「界面不许说谎」正是 **Day 12 自己立下的规矩**
（那条规矩的起因，就是一个「看着是已收藏、其实什么都没存」的按钮）。

## 六、这次学到 / 记住的

1. ⭐ **「东西不见了」先分清是「真丢」还是「没看见」。**
   两者要做的事完全相反：真丢要抢救数据，没看见要修界面。
   **判据只有一个 —— 让浏览器自己把值读出来**，别靠推测。
2. ⭐ **本地存储按网址隔离。** 本地文件和线上网址是两只抽屉。
   以后凡是要他「打开网页确认」，一律先让他看清**地址栏**。
   （先写进了空状态文案 —— **但只放那儿不够**，他照样又问了一次；
   同一晚就落成了**页面顶部的地址提醒**，见第八节。）
3. **界面不许说谎**（Day 12 的老规矩，这次又用上了）：
   数据对不上就**如实说对不上**，不能默默显示成「空」。
4. **正文用正文档、辅助信息用辅助档** —— 收藏列表的正文原来用了 13px 辅助档，
   读起来费劲，这次一并纠正。
5. **断言按实测值写**：长文本那条我第一次写了「≥ 5 行」，
   实际是 4 行 —— 又踩了 Day 19 当天那条坑（预期值先打出来再写）。

## 八、他第三次问同一件事之后：加了一道「地址提醒」

> 这一节是**同一晚补的**，他点头的原话：「要给页面加一道「防呆提示」」。
> CHANGELOG 里也有一条简版（「Day 19 收工后（补 2）」）。

### 8.1 前两次的应对，为什么没解决问题

| 第几次 | 我做了什么 | 结果 |
| --- | --- | --- |
| 第一次（21:40） | 去他浏览器里把记录读出来，告诉他「没丢」，并**在空状态里补了一句**「按网址分开存」 | 他**又问了一遍** |
| 第二次（22:13） | 把那次截图放大量出「跑的是旧代码」，确认他开的不是正式网址 | 他点头让加防呆 |
| 第三次 | —— | **加了这道提醒** |

⚠️ 关键判断：**问题不在解释得不够，而在解释放错了地方。**
他看到的是「**还没有收藏**」五个大字，压根不会去读下面那行小字；
而且他用的那个窗口（WorkBuddy 内置预览）**看不到地址栏**，
所以「你自己看一眼地址」这条路对他根本走不通。
→ **页面得自己说，而且要大声说、在顶部说。**

### 8.2 它长什么样、说什么

一条暖橙色的条，出现在**导航下面、元信息行上面**（三个视图都看得见），内容是：

```
你现在打开的不是正式网址
这个地址下的收藏和打卡是空的 —— 你的记录存在下面那个正式网址里，不是丢了。
你现在在这儿： 本地文件（双击打开的那个 html）
正式网址是：   https://source-board.app.workbuddy.host/
这个地址下：收藏 0 条 · 打卡 0 天
[ 用浏览器打开正式网址 ]
```

**「不是丢了」这四个字是这条提醒存在的全部理由。**

### 8.3 五个刻意的选择（都写进代码注释了，免得以后被「优化」掉）

1. **只认「完全一样」才算正式地址** —— 连协议一起比（`http` 与 `https` 是两个来源）。
   只比域名的话，用 http 打开会被判成「就在正式地址上」，**该说的提醒反而不说了**。
2. **条数当场算**（`S.countFavorites()` / `S.allDays()`），不缓存、不写死 ——
   他刚在这个地址下收一条，数字就得跟着变；否则**这条提醒自己就在说谎**。
3. **地址一律现取**（`location.origin` / `config.officialOrigin`），
   不写进文案里 —— 写死的地址迟早跟现实对不上。
4. **按钮指向「正式网址上的同一页」**（`正式网址 + location.hash`）。
   他是在「我的」页发现问题的，跳回首页等于让他自己再点一次。
5. **正式网址上它连画都不画**（不是画了再藏），
   所以正常用户完全感觉不到它存在 —— 版面跟以前一模一样。

### 8.4 怎么证明

脚本 `verify-addr-warn.mjs`（已归档，三种跑法）：

| 模式 | 期望 | 结果 |
| --- | --- | --- |
| `local` 本地服务器 | 提醒**必须出现** | **23 / 23** |
| `file` 双击本地文件 | 同上，且地址那行要说人话（不能是 `null`） | **15 / 15** |
| `live` 正式域名 | 提醒**必须完全不出现** | **10 / 10** |

最硬的两条断言：

- ⭐ **不刷新页面、只切视图**：先在本地地址下写一条收藏 → 数字变「1 条」；
  再把收藏删掉 → 数字**当场**变回「0 条」。中间用 `window.__noReloadMark` 证明页面没重载过。
  （这条才真正证明「数字是算的，不是开机算一次缓存下来的」。）
- **正式域名上容器里一个字都没有**，且整页文字里搜不到这句提醒。

回归：逻辑层 73 / 73、线上全接口 35 / 35、收藏那条 16 / 16；全程 JS 报错 0 条。

### 8.5 又一次踩了同一个坑（记下来）

两条断言挂掉，**都不是产品的问题**：

1. 用 `Page.navigate` 跳到**和当前完全一样**的地址 —— 浏览器认为「还是这一页」，
   **不会重新加载**，于是页面还挂着旧渲染，三条断言全挂 → 改成 `Page.reload`。
2. 断言「数字归零后正文变回『是空的』」—— 但我当时**把打卡那条留着了**（打卡 1 天），
   文案**正确地**仍然是「也存了一份记录」。判据应该是「两个数都为 0」。

→ 跟当天上午那条「预期值凭想象写」是同一个毛病的两种变体：
**测试写错时，先怀疑自己的断言，别先怀疑产品。**
