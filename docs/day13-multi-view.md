## 三、三个视图怎么分

| 视图 | 地址 | 放什么 |
| --- | --- | --- |
| 今日 | `#/home` | 统计卡 + 今日语录 + 打卡（原首页的精华） |
| 内容库 | `#/library` | 三列榜单：认知·自律 / 名人访谈 / 政策·风口 + 四种状态对照区 |
| 我的 | `#/me` | 我的收藏 + 最近 7 天打卡记录 |

导航是页首的三个标签，`aria-current` 标当前页（键盘读屏也能认出来）。

## 四、代码怎么改的（按分工）

| 文件 | 改了什么 |
| --- | --- |
| `index.html` | 三个 `<section class="view">` 容器 + 导航标签 |
| `config.js` | 路由常量（视图 id ↔ 哈希）、「读取延迟」常量（420ms，模拟网络） |
| `rules.js` | 纯函数：`viewKey()`（把地址里那截洗成干净的视图名）/ `viewIdFromHash()`（地址 → 视图 id，认不出回默认）/ `hashOfView()`（视图 id → 地址）——**不碰页面**，所以能在命令行单独测 |
| `data.js` | 三个视图的名字/说明 + 四种状态的文案（文案集中一处，不许在代码里散写） |
| `store.js` | 没动（打卡和收藏本来就该跟着「我的」视图走，数据层不关路由的事） |
| `app.js` | 监听 `hashchange` + 首次加载解析地址；统一的状态渲染器 `ListState()`；内容库的模拟数据源（正常 / 空 / 会失败） |
| `style.css` | 导航、视图显隐、四种状态、对照区的样式 |

**核心原则**：切视图只改地址（`location.hash`），剩下的交给 `hashchange`
事件统一处理——**只有一个入口**，不存在「点导航一套逻辑、按返回键另一套」。

## 五、四种状态

列表统一走一个渲染器，长一个样：

| 状态 | 长什么样 |
| --- | --- |
| 空数据 | 「这一列还没有内容」+ 说明（等收录后会出现条目） |
| 加载中 | 骨架占位条 + 「正在读取内容…」 |
| 出错 | 「内容没读出来」+ **重试按钮**（留一条活路，不让人干瞪眼） |
| 正常 | 真正的内容条目 |

为了让四种状态能**一屏看到**（今天要交截图），内容库顶部加了一个
「四种状态对照」演示区，下面还有「把内容库切成：正常数据 / 空数据 / 读取失败」
三个按钮——正式产品不会有这块，纯粹是为了开发期对照和验收。

**顺手揪出一个真 bug**：错误状态的重试按钮最早写死了 `id="btn-retry"`，
而页面上它被画了两次（演示区 + 真列表）——**id 重复**，HTML 不允许。
真机测试点重试时点到了演示区那个没有事件的按钮。改法：删掉写死的 id，
重试动作通过 `onRetry` 回调传入。

## 六、怎么验证的（两层）

1. **命令行**（不开浏览器）：`rules.js` 的路由纯函数 78/78 全过
   —— 正常地址、非法地址、空地址、大小写、来回转换。
2. **真机 Edge**（CDP 驱动真浏览器）：109/109 全过，覆盖：
   - 三个视图互相切换、地址跟着变、导航高亮跟着变；
   - **浏览器「返回」键**真的回到上一个视图（History 集成）；
   - 刷新后**停在同一视图**；
   - 切数据源时先经过「加载中」再变成目标状态（0.42 秒，轮询抓取不靠猜）；
   - 出错 → 点重试 → 重新读取 → 还是出错（数据源就是「会失败」的，**不说假话**）；
   - 全程无 JS 报错。
