# Day 12｜把「收藏」做实

> 对应打卡 Day 12。文件：`docs/day12-favorites-persistence.md`
> 相关：`docs/day11-checkin-persistence.md`（同样的毛病，打卡先修过一次）

## 一、问题是什么

「收藏」这颗按钮**看起来是好的**：点一下会变成「已收藏」，还会高亮成暖橙色。
但只要刷新页面，它就变回「收藏」——**什么都没存下来**。

深挖下去，其实是**三个毛病叠在一起**，第三个最要命：

| # | 毛病 | 后果 |
| --- | --- | --- |
| 1 | 收藏状态保存在一个内存对象里（`quoteSaved`） | 刷新、关页面就没了 |
| 2 | 键是「**第几条**」（数组下标） | 以后改了语录文字、调了顺序、删掉一条，**收藏会跳到别的句子上去** |
| 3 | **收藏完了没有任何地方能看到收藏了什么** | 这颗按钮等于把东西扔进黑洞——除了再点一遍，永远见不到它 |

第 3 条是这次最值得说的：前两条是「存不住」，第 3 条是「**存住了也没用**」。
一个按钮如果按完看不到任何结果，它就不算一个功能。

## 二、怎么描述这个问题（Day 10 那一课的应用）

> **在哪儿**：首页「今日认知语录」卡里的「收藏」按钮
> **我做了什么**：点了一下「收藏」，它变成「已收藏」
> **我看到了什么**：刷新页面，它变回「收藏」；而且我找不到任何地方能看到我收藏过什么
> **我希望它怎样**：收藏要**真的存下来**，而且**要能看见、能翻回去**

四要素齐全：位置 + 复现步骤 + 事实 + 期望。
反例：「收藏有点问题」「优化一下收藏功能」——这种说法 AI 只能反问或者乱改。

## 三、改法

### 1. 语录加稳定 `id`

`data.js` 里每条语录加一个固定名字（`munger-contribute` / `clear-systems` …），
收藏时**存这个名字**，不存「第几条」。

> 这是 Day 11 打卡换来的教训，现在也升格成了硬规矩
> （`AGENTS.md` 第 4 条第 10 项：**存记录一律存 id，不许存第几条**）。

### 2. `store.js` 里加收藏这只**独立抽屉**

```
打卡：growth-site.checkins.v1     { version: 1, days: {...} }
收藏：growth-site.favorites.v1    { version: 1, ids: [...] }
```

**为什么不跟打卡挤在一个键里**：两件事的格式以后会各自演化。
混在一个抽屉里，哪天改了收藏的格式，就得连打卡的记录一起迁移——
分开就各改各的，互不影响。

`store.js` 仍然是**全项目唯一碰 `localStorage` 的文件**（规矩第 4 条第 6 项），
所以页面上一个 `localStorage` 都没多出来。读回来的脏数据一律清洗：
数字、空串、重复全去掉；坏 JSON、版本号对不上，一律当空，**绝不让页面报错**。

### 3. 语录卡底部加「我的收藏」

这是把「存住了」变成「有用了」的那一步：

- 标题右边写着「2 条 · 点一条跳过去」；
- 每条显示语录前半句 + 作者，长句子省略号截断，鼠标停上去看全文；
- **点一条 → 跳到那条语录**；
- **一条收藏都没有时，这块区域完全不出现**（不是空壳子）。

### 4. 按钮状态**从存储里读**

改之前：按钮文字来自内存变量 `quoteSaved[quoteIndex]`。
改之后：`S.hasFavorite(q.id)` —— 每次重画都去问存储。

**为什么这点很重要**：只要状态来源是内存，界面就有机会「说假话」
（显示已收藏、其实没存）。改成问存储之后，**界面不可能说谎**。

另外，点击的顺序也定死了：**先写存储，再重画界面**。
顺序反了就会出现「屏幕上勾上了、其实没存住」。

## 四、验证（都是实测）

分两层测，这是把「算/存/画」分开的好处——**逻辑层不用开浏览器就能测**。

| 测什么 | 怎么测 | 结果 |
| --- | --- | --- |
| **存储逻辑**（`verify-favorites-rules.mjs`） | Node 里用 `vm` 造一个假窗口，把 `config.js → rules.js → store.js` 按真实顺序跑一遍；共用同一份假存储再跑一遍 = 「刷新页面」/「关掉浏览器重开」 | **37 / 37** |
| **真机行为**（`verify-favorites.mjs`） | 真的开 Edge、真的点按钮、真的刷新、真的关掉浏览器再打开、真的抓窗口截图 | **58 / 58** |
| Day 10 量尺回归 | 三列等高 / 字号 4 档 / 对比度 / 可点尺寸 / 窄屏溢出 | 见当日运行结论 |
| Day 11 打卡回归 | 打卡的 51 项一条不许红 | 见当日运行结论 |

逻辑层覆盖的边界情况：**脏数据**（数字、空串、重复、`ids` 不是数组、整个值不是对象、
坏 JSON、版本号对不上）、**存储不可用**（浏览器没有 `localStorage`、一写就抛错）、
**两只抽屉互不干扰**、**`clearAll` 两只都清**。

真机层最硬的三条：

1. **刷新页面后**：收藏还在、列表还在、按钮仍是「已收藏」——而且按钮状态是
   **从存储读出来的**，不是记住的；
2. **关掉浏览器、用同一个档案重新打开**：收藏还是两条；
3. **取消收藏后刷新**：确认是真的取消了，**不是只在屏幕上变了**。

## 五、路上踩的三个坑（都值得记）

### 坑 1　写验证脚本时，行内注释忘了写收尾的 `*/`

```
const second = boot({ backing: map });   /* ← 这就是「刷新」
```

这样写，**后面的整段代码都被吃进注释里**了。报错是 `Unexpected end of input`
（在文件末尾），完全看不出问题在前面的注释里。

排查过程也记一下：写了个小脚本数括号——`{` 46 个、`}` 45 个，**多了一个**；
再找出「括号深度回到 0 的行号」，发现 127 之后再也没有回到 0，问题定位到第 128 行往后的区块。

> **教训**：报错位置在文件末尾时，**不一定是末尾的问题**，很可能是前面有个没闭合的东西。

### 坑 2　抓窗口差点又拍到别人的浏览器

抓图脚本按**窗口标题**找窗口。同一个站点我自己的浏览器也开着，标题一模一样，
旧逻辑会按「面积最大」选中 —— **可能拍到我自己那个窗口，当成"收藏后"的证据交出去**。
（Day 10 真出过这个事。）

这次改成：先查出「命令行里带本档案目录」的**所有** msedge 进程号（一串，
因为 Edge 的窗口挂在某个子进程上、不是启动器），只认这些进程的窗口；
**一个都对不上时，直接失败、不产出图片，绝不退回「面积最大」**。

实测日志：

```
标题里含「大学生成长网站」的可见窗口共 2 个：
    0x420476   pid=12488   面积=3732960   标题=大学生成长网站 - 个人 - Microsoft Edge    ← 用户自己的
    0x2880A7E  pid=27488   面积=2888655   标题=大学生成长网站 - 用户配置 1 - Microsoft Edge ← 我们的
按进程号 [8868, 25076, 27488, ...] 过滤后剩 1 个候选
选中窗口：0x2880A7E  pid=27488  标题=大学生成长网站 - 用户配置 1 - Microsoft Edge
```

注意：按面积最大的那个（3732960）**是用户的窗口**。要是没这一步过滤，就拍错了。

### 坑 3　一个「假失败」：强杀浏览器导致刚写的记录丢了

第一次跑真机测试，**57 通过 / 1 失败**：

```
✗ 七、关掉浏览器，用同一个档案重新打开（最硬的证据） → 打卡记录也还在
  ← 实际 undefined，期望 ["read"]
```

收藏的两条都在，偏偏刚点的打卡没了。看着像真 bug，但**不是**：

- 浏览器的本地存储是**异步落盘**的（什么时候真正写进磁盘由它自己决定）；
- 我关浏览器用的是 `taskkill /F`（**强杀**）。刚点完打卡一两秒就被杀，
  那一条还没落盘；而更早收藏的两条早就落了盘，所以活着。
- **真人关窗口不会这样**——点右上角的叉会走正常关闭流程，把该写的都写完。

改法：关闭时**先请浏览器自己体面地退出**（通过调试端口发 `Browser.close`，
等价于点那个叉），等它真退出；实在不退出再强杀。

改完重跑：**58 / 58 全过**。诊断成立。

> **这条是最值得记的**：一个失败的测试，可能是**应用错了**，也可能是**测试错了**。
> 判据是「哪种解释能被实验证实」——换个体面的关闭方式，失败就消失了，
> 说明问题在关法上，不在存储上。
> 但**不能只靠"想通了"就把它当通过**，得重新跑一遍拿到干净的绿。
