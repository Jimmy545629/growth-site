# 发布前检查 · pre-release-check

## 这个技能解决什么问题

没有它的时候，一次改动的收尾是「提交 → 发布 → 告诉 Jimmy 已上线」。
中间**没有一个固定的动作去回答「这份代码到底能不能发布」** ——
靠的是我（AI）当场记得多少。我记得住的时候是运气，记不住的时候就是把问题带上线。

有了它：**收尾流程里插进一条命令**，12 项检查一次跑完，红就是红、绿就是绿。

> ⭐ 设计上最要紧的一句话：**「没查」不等于「通过」。**
> 所以输出是三态（通过 / 失败 / 未检查），不是两态。
> 断网了、起不了子进程了 —— 检查项会明说「未检查」，
> 而不是安静地跳过去、让人以为一切正常。

## 怎么跑

在项目根目录（`C:\Users\33386\WorkBuddy\growth-site`）里：

```
node skills/pre-release-check/check.mjs
```

参数：

| 参数 | 干什么 |
| --- | --- |
| `--no-online` | 跳过 C 组联网检查（离线时用）。被跳过的项标「未检查」 |
| `--only A1,C1` | 只跑指定项（调试用；对应「卡住降级」的最小版：只查凭据 + 线上可达） |
| `--online-base <url>` | 临时换线上地址 —— **只用于验 C1 真的会红**，平时不要带 |
| `--shot <out.png>` | C1 顺手截一张首屏图当证据（留档用） |
| `--walk` | 强制走「目录遍历 + .gitignore 解析」的文件清单通道（对比调试用） |
| `--list-files` | 只把文件清单打出来，不跑检查 |
| `--root <目录>` | 指定项目根（本技能的副本在别的目录里调用时用） |

**依赖**：不用 npm、不用 node_modules、不 spawn 子进程 —— **只有 C1 一处破例**：
它要在本机 Edge 里真打开一次（用 Playwright 启动，装在 WorkBuddy 的 node 工作区里）。
破例的代价由「三态」兜住：浏览器起不来就标「未检查」，绝不冒充通过。

**退出码**：有失败项 → `1`；只有通过/未检查 → `0`。
可以直接用在 `&&` 后面，例如「检查过了才允许提交」。

## 检查项：12 项，分三组

### A 组 · 安全红线（碰了就是事故）

| 代号 | 检查什么 | 怎么算通过 |
| --- | --- | --- |
| **A1** | 仓库里有没有真实凭据 | 拿 9 类敏感凭据形状去扫全部文件 → **代码与配置里 0 处命中** |
| **A2** | `.env` 全族有没有被忽略 | `.env` / `.env.local` / `.env.production` / `.env.development` / `.env.test` / `.env.staging` 六个变体**全部**被 `.gitignore` 挡住 |

关于 A1 的两条有意设计：

1. **报告只打印代号和打码片段，绝不回显命中原文。**
   一份检查报告自己把凭据抄一遍，就成了新的泄漏面。
   代号含义写在 `check.mjs` 的注释里，**不进任何文档** —— 同一个理由。
2. **代码里的命中判「失败」，文档里的命中判「通过 + 备注」。**
   文档里出现这些词，通常正是在**讲这件事本身**（比如 Day 23 记录的「特征词清单」）。
   它和「代码里藏了真凭据」是两回事，不该共用一个结论。
   ⚠️ 是**通过 + 备注**，不是「忽略」：位置一条不少地摆在报告里，看得见。

### B 组 · 技术硬规矩（`AGENTS.md` 第 4 条）

| 代号 | 检查什么 | 为什么 |
| --- | --- | --- |
| **B1** | 没有 `<script type="module">` | `file://` 下模块脚本会被浏览器直接拦掉 → 整页白屏 |
| **B2** | 没有「白名单外」的在线资源 | 断网必须能用；线上也不该依赖第三方存活 |
| **B3** | 没有构建步骤 | 不出现 `package.json` / lock 文件 / `node_modules` —— 双击就要能用 |
| **B4** | 没有 `innerHTML` 拼接 | 内容里有个 `<` 就会让整页错乱；文字只能走 `textContent` |
| **B5** | `localStorage` 只在 `store.js` | 以后换云端只改那一个文件 |
| **B6** | 不用 `toISOString()` 取日期 | 它给的是 UTC，国内晚上 8 点后打的卡会被记到第二天 |
| **B7** | 脚本加载顺序对 | 固定为 `workbuddy-cloud-sdk → config → db → cloud → rules → store → data → app`，换一个就白屏。**Day 27 起最前面多了本地 SDK**（见 B2 那段） |
| **B8** | `assets/` 文件名规范 | 小写 + 连字符 + 不带空格，避免本地路径出问题 |

#### ⚠️ B2 的「白名单」Day 27 清空了 —— 那条例外自己变成了 bug

原来这里放行过**唯一一个例外**：云端 SDK 的 jsdelivr CDN（Day 17 加的）。
放行的理由当时成立（纯静态 + 零构建，引 npm 包就要多一道构建步骤），所以判它 PASS 不算误报。

但 **Day 27 实测发现：jsdelivr 在国内直连不通**（`HTTP 000`；DNS 能解析、TCP 连不上；
浏览器里那条请求 `transferSize: 0`）→ `window.WorkBuddyCloud` 是 `undefined`
→「今日热点」和「内容库」**整块显示「没读到」**。
于是 SDK 被收进本地 `assets/workbuddy-cloud-sdk.js`（66 KB），**白名单随之清空**（现在恒为 `null`）。

> 这一条值得单独记住：**「放行」不等于「没问题」。**
> 检查项跟项目真实约定对齐（不误报）是对的；
> 但那个被放行的例外，仍然要**有人定期回头问一句「它还好不好」** ——
> 它今天就成了线上最大的那个 bug。

### C 组 · 发布前状态

| 代号 | 检查什么 | 怎么算通过 |
| --- | --- | --- |
| **C1** | 线上地址还活着吗 —— **用本机 Edge 真打开一次** | 五条全满足：HTTP 200 且没被跳走 / 连到的不是本机 IP / 标题里有「大学生成长网站」/ **JS 真把骨架画出来了**（导航 3 个 + 统计卡 3 张 + 语录有字 + 正文够长）/ 没有未捕获的 JS 异常 |
| **C2** | 线上跑的是不是本地这份代码 | 逐文件比 md5，**全部一致** |

C2 比对的文件不是写死的清单，而是**从 `index.html` 里引用关系自动推出来的**：
`index.html` + 引用的 `*.css` / `*.js` / `*.svg`（素材类的大文件不比对）。
所以以后新增了 js 文件，它自动进入比对范围，不用改检查脚本。

#### ⚠️ C1 为什么必须是「真浏览器打开」（2026-10-22 改）

它原来是「Node 里 `fetch` 一下，`status === 200` 就算通过」。这个判据被现实打脸过：
本机的代理把 `source-board.app.workbuddy.host` 转给了 `127.0.0.1`，
`curl` / `fetch` 都拿到一个**假 200**，检查项于是打了绿勾 —— 而线上当时其实是坏的。

> **假绿比不检查更危险。** 不检查你会去看看；假绿你就再也不会看了。

换成真浏览器之后，同一件事一眼就能看出来：它会告诉你「浏览器实际连到 127.0.0.1」。
而且真浏览器还能看见两样规则层、`fetch` 层都测不出来的东西：

1. **JS 到底跑没跑。** Day 17 出现过「线上整页 JS 全不执行、只剩空骨架，本地却正常」。
   `fetch` 拿到的是 HTML 源码 —— 源码里写着 `#tabs`、`#stats` 这些空容器，永远「看得见」；
   只有真跑一遍才知道里面有没有被画上东西。
2. **有没有未捕获异常**（`pageerror`）、**有没有请求失败**（`requestfailed`）。

在报告里，C1 通过时会把「看见了什么」一并印出来，比如：

```
[通过]  C1   线上地址可访问（真浏览器）   Edge 真打开过 — HTTP 200 · 349 ms · 画出 3 个导航 / 3 张统计卡
       · 真浏览器所见  DNS 直连解析：...
       · 真浏览器所见  HTTP 200 · 首屏 349 ms
       · 真浏览器所见  实际连到 ...:443
       · 真浏览器所见  TLS 证书签发者：...
       · 真浏览器所见  标题「今日 · 大学生成长网站」· 导航 3 个 · 统计卡 3 张 · 语录 186 字 · 正文 1323 字
```

**TLS 证书签发者那一行也是判据的旁证**：真被中间人接管时，签发者会变成一张本机自签证书。

两个实现上必须记住的坑：

- **标题要用「包含」判，不能全等。** `app.js` 会按当前视图改标题，
  真实标题是「今日 · 大学生成长网站」。第一版用全等，一跑就误报。
- **不写 `import 'playwright'`。** 它装在本机的 node 工作区里、不在项目 `node_modules` 下，
  而 ESM 的 `import` **不认 `NODE_PATH`**，直接 import 必然报「找不到模块」。
  改用 `createRequire(目录)` 按老式规则去找（见 `loadPlaywright()`）。

## 关键实现细节（改的时候别踩）

1. **匹配前必须剥注释。** 项目里的注释大量提到 `innerHTML` / `localStorage` /
   `toISOString`（都是在讲「别用它」）。照着原文匹配必然误报。
   → `.js` 剥掉行注释和块注释，`.html` 剥掉 HTML 注释，**换行保留**（行号才不错位）。
2. **失败必须指到「文件:行号」**，只报「有问题」等于没报。
3. **零子进程**（C1 除外）。在受限环境里 `spawn` 会被挡（`EBUSY`），脚本就会假装检查不了。
   所以文件清单有两条通道：
   - `git ls-files`（权威：只含会被提交的文件）
   - 目录遍历 + 自己解析 `.gitignore`（降级通道，**会包含还没 `git add` 的新文件，更严格**）
   实测过两条通道的清单差异，只有「新建但未 `add` 的文件」这一处，符合预期。

## 故意弄坏验证（2026-10-11，Day 25 实做）

**检查工具最怕的是「永远绿灯」** —— 那样它比没有还糟，因为它给人虚假的安心。
所以第一次做完，必须**故意弄坏**来验它真会红。

| 轮次 | 弄坏哪一项 | 预期 | 实际 |
| --- | --- | --- | --- |
| ① | 在 `assets/config.js` 里塞一行假的 S1 形状凭据 | A1 判失败，指到该行 | 见 `docs/screenshots/day25/` |
| ② | 在 `index.html` 里加一个白名单外的在线字体 | B2 判失败，指到该行 | 同上 |

两轮都**立刻改回原样**，改回后重跑必须恢复全绿 —— 这才叫闭环。

## C1 改成真浏览器后的三轮验证（2026-10-22 实做）

换判据等于换了一把尺子，必须重新证明它既会红、也不会乱红。
用 `--online-base` 临时换地址来造场景（不碰真正的那一行常量）：

| 轮次 | 指向哪儿 | 预期 | 实际 |
| --- | --- | --- | --- |
| ① | 真实线上地址 | 域名若真挂了就判失败 | **判失败**：`net::ERR_NAME_NOT_RESOLVED`，一条结论说清原因（当天线上域名确实已不存在） |
| ② | 本机 `http://127.0.0.1:8765/`（本地起一份项目） | 页面渲染全部通过，但「连到本机」必须判失败 | **恰好 2 处失败**：DNS 解析到 127.0.0.1、浏览器连到 127.0.0.1；同时打印「导航 3 个 / 统计卡 3 张 / 语录 186 字」→ 证明正面判据是对的 |
| ③ | `https://www.baidu.com/` | 能打开，但标题不符 → 失败；同时应报出真实 IP 与证书签发者 | **判失败**，理由「标题里没有『大学生成长网站』」；附 `实际连到 [2409:...]:443`、`TLS 签发者 GlobalSign RSA OV SSL CA 2018` |

②这一轮是重点：它同时验证了「正面判据能过」和「防冒充判据会红」——
只验前者会得到一个永远绿灯的检查，只验后者会得到一个永远红灯的检查。

## 加一项新检查，改哪里

在 `check.mjs` 里加一个 `checkXX()`，然后加到文件末尾的 `ALL` 数组里。
三件事要一起想清楚：

1. **怎么算通过**（要有明确判据，不能靠眼看）；
2. **会不会误报**（有没有注释、文档、白名单之类要绕开）；
3. **查不了的时候怎么标**（用「未检查」，不要偷偷算通过）。
